API Overview Doc Generator（接口全貌文档）

基于代码生成《接口全貌文档》，覆盖 HTTP 端点、服务间调用、消息队列。脚本先行（parse_api.py --scaffold）机械提取方法/路径/参数/返回类型，AI 只补接口说明列。支持 PHP/Java/Go/Python/Node.js 任意后端栈。

执行全流程（5 步）

01 确认脚本就绪
动作
先扫描项目代码：读取 Controller/Router 目录，确认技术栈（Spring Boot/Flask/Gin/Laravel/Express）、路由定义方式、路径前缀是否常量注入。再定制编写 scripts/<服务名>/parse_api.py。
产出
parse_api.py 已存在（支持 --scaffold / 默认验证 / --scan-only 三模式）。
红线
不存在则生成后再进下一步，绝不允许无脚本直接靠 AI 提取。
02 生成骨架
命令
python scripts/<服务名>/parse_api.py --scaffold > /tmp/scaffold.md
产出
骨架表已自动填入 HTTP 方法、完整 URL、参数、返回值类型、源码注释、模块分组。这 5 列为确定性数据，不得修改。
03 填入接口说明
动作
有注释 → 保留注释内容；无注释 → 按方法名推导中文描述（list→获取分页列表、save→新增、update→更新、delete→删除、get→详情、export→导出）。
产出
骨架表第 5 列（接口说明）全部填完。
04 追加服务调用与消息队列
服务间调用
扫 @FeignClient / RestTemplate / http.Client / gRPC → 调用方→被调用方、方法签名、地址/路径、降级/重试。
消息队列
扫 @JmsListener / @RabbitListener / Kafka Consumer / Redis Pub-Sub → Topic/Queue、消息用途、消息体结构。
产出
三章节完整文档（HTTP 接口 + 服务间调用 + 消息队列）。
05 交叉验证
命令
python scripts/<服务名>/parse_api.py（默认验证模式）
Gate
◆ 退出码 0 = 源码与文档一致（✅ 完成）；1 = 存在差异 → 修正差异后重跑直到 0。
完成标准
退出码 0 + 三章节已生成 + 每章端点数量与源码一致。

关键信息

触发条件

  • 微服务上线前需要标准化接口清单
  • 接口文档缺失或过期
  • 集成测试、外部对接前
  • 任意后端栈：PHP / Java / Go / Python / Node.js

排除边界

  • 业务模型/数据模型分析 → doc-business-risk
  • 项目架构分析 → doc-project-architecture
  • 架构设计图/流程图 → doc-architecture-diagram
  • 项目启动文档 → doc-project-startup
  • 编写接口代码/修复 Bug → AI Dev Workflow

产出物

  • <服务目录>/docs/接口全貌.md
  • 三章节：HTTP 接口总览 + 服务间调用 + 消息队列通信
  • 配套 parse_api.py 验证脚本

禁止行为清单

❌ 绝对禁止

  • 不先跑 --scaffold 就手工生成
  • 随意翻译方法名动作词（del 不改 delete）
  • 跳过骨架中的确定性列
  • 对相似端点不补中文描述
  • 生成后不跑验证
  • 验证不通过就提交
