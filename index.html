欢迎浏览 👋 这里是按软件工程全生命周期编排的 Skill 工程体系：11 大类、74 个在册 Skill，从需求理解、方案设计、编码开发、测试排障、安全审计到交付部署，每道工序均由可执行的方法论、机械臂脚本与约束规范支撑。以软件工程师（FDE）的角色切入真实业务场景，每个环节都可交付可运行、可验证、可复用的工程成果。

本页面为「导览解说版」总览：研发层 9 大层次配有执行流程可视化，逐一呈现每个 Skill「怎么执行」；业务层与外部开源层以目录登记卡片展示（详情见 index/10-业务层.md 与 index/11-外部开源.md，外部开源层为索引卡，需 clone 上游仓库并遵守其归因约定）。每个 Skill 均由 SKILL.md + 机械臂脚本 + 策略约束构成完整「项目体」——可独立调用、可组合编排、可全流程复现，是可审计、可演进、持续沉淀的工程资产。

链路说明：主链按 SKILLS-INDEX.md「生命周期与依赖（串）」编排，研发层 9 大层次 + 基础设施承托 STEP 01–11，业务层（RAG/前端/视频/Python/Orca）与外部开源层（9 卡）作为横切能力按需接入；rag-context-engine、reporting-art 为双栖 Skill 跨层复用。↩ 纵向：业务层按技术域触发（产出写入项目目录），外部开源卡先 clone 上游再加载其 SKILL.md。

闭环完整：研发层 9 大层次已形成需求 → 设计 → 开发 → 测试 → 排障 → 复盘 → 沉淀知识库 → 安全审计的完整工程闭环；其中 20 个核心 Skill 已在本目录生成可视化卡片（含 UEP、ai-digital-employee 两个归档工程的历史页面），无需通读源码即可掌握其执行脉络。业务层 10 个在册 + 2 套件为目录登记，外部开源层 9 张索引卡需 clone 上游后使用。剩余在册 Skill 的可视化 HTML 可通过 skill-flow-viz-generator 逐步生成。

价值所在：每个 Skill 都是一个由 SKILL.md + 脚本 + 策略 + 约束组成的完整「项目体」，而非单一文件；它们共享统一的治理标准与视觉语言，既可独立使用、也能协同编排，共同构成一套可复用、可审计、可演进的 AI 工程能力底座。
