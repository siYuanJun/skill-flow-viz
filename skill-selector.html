Skill Selector（Skill 选择顾问）

工具/入口型顾问：用户发一句粗糙需求 → 反问 ≤2 个澄清问题 → 对照 SKILLS-INDEX 总路由表定类别 → 进 index/ 分类文件取详细路由 → 产出带绝对路径、可直接复制执行的提示词（含多 skill 组合、多 agent 编排）。

执行全流程（4 步）

01 理解需求
动作
收用户一句粗需求（例：「我想把聊天里的方法论变成 skill」）。用户只发观点时，AI 代为补全澄清问题与路由。
输出
需求意图一句话归纳。
02 澄清（≤2 问）
动作
最多 2 问，不堆砌：① 输入材料形态？代码 / 会话 / 文档 / 无；② 产出物形态？skill 工程 / 文档报告 / 提示词 / 测试脚本 / HTML 可视化。用户能明确回答则少问。
Gate
◆ 用户确认澄清答案后进入路由。
03 路由（读索引不复制）
动作
读 SKILLS-INDEX.md 总路由表（第三节）定类别 → 进对应 index/xx.md 取分类详细路由 + docs/SKILL工程组合技巧/ 案例 → 定主/辅助 skill、是否多 skill 组合、是否多 agent 编排。
约束
路由事实必须来自索引文件，不凭空编 skill。
04 产出可复制提示词
动作
生成可复制提示词：skill 绝对路径 + 机械臂脚本绝对路径（若有）+ 输出目录 + 占位符 + 多 agent 编排（如适用）。参考 references/prompt-template.md。
产出
推荐主/辅助 skill 清单 + 路由理由（一行）+ 可直接复制执行的提示词。

关键信息

触发条件

  • 用户说「不知道用哪个 skill / 帮我选 skill / 该用哪个工程为我服务」
  • 用户给一句粗需求，想要可复制的提示词发给另一个 agent
  • 需要多 skill 组合推荐 / 多 agent 编排提示词

排除边界

  • 纯代码编写、修 bug、部署 → 转入对应 skill
  • 已明确指定某个 skill 的直接调用 → 不拦截
  • 具体执行任务 → 本 skill 只产出提示词，不代做

产出物

  • 推荐主/辅助 skill 清单 + 路由理由
  • 可复制提示词（绝对路径 + 输出目录 + 占位符）
  • 多 agent 编排提示词（如适用）

关键原则

读索引不复制

路由依据 SKILLS-INDEX.md 总路由 + index/ 分类文件，不内嵌 skill 目录，避免漂移。

少问多产

澄清 ≤ 2 问，用户给观点就代为完善，不追问堆砌。

可复制优先

输出是可直接执行的提示词，不是分析报告。替换占位符即执行。

工具/入口型

先判定场景再路由，不越界执行任务。对标 debug-problem。
