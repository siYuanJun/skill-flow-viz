Git Auto Commit（Git 自动提交助手）

一键完成 Git 提交流程：分析变更 → 生成规范注释 → 暂存 → 提交，提交后经用户人工确认再推送。Conventional Commits 中文前缀，一次确认不重复打扰。push 属对外操作，绝不自动执行。

执行全流程（4 步）

00 一次确认（目录 + 提交范围合并）
动作
用 pwd 显示当前目录，展示变更概览（文件数 + git diff --stat 行数）。一次询问（推荐项放第一个）：
选项
✅ 推荐：确认在此目录提交（提交全部）；备选：只提交部分变更；备选：换目录。
规则
用户选推荐项 → 直接进入步骤 1，提交前不再问第二次；push 仍需单独确认。防止误提交且不重复打扰。
01 感知状态
命令
git status --porcelain · git diff --stat · git diff --cached --stat · git branch --show-current · git remote -v
决策
无变更 → 告知用户结束；只有未跟踪文件 → 询问是否加入；有未暂存变更 → 进入步骤 2。
02 分析变更 + 生成 Commit Message
动作
读取 git diff 和 git diff --cached，按变更类型匹配 Conventional Commits 前缀。
前缀表
feat: 新功能 · fix: 修复Bug · docs: 文档 · refactor: 重构 · style: 样式/UI · test: 测试 · build: 构建/依赖 · perf: 性能优化 · chore: 杂项
规则
格式 <type>: <中文简述>（一行 ≤50 字）；多个不相关变更 → 拆成多次提交；末尾自动追加 Co-Authored-By。
03 提交 + Push 人工确认
提交
git add -A → git commit -m "<message>"
Push 规则
提交成功后不自动 push。显示推送摘要（分支名 + commit hash + message + 远程目标），明确询问用户是否 push。仅在用户明确确认后执行 git push。用户说「只提交不推送」→ 不 push，直接结束。
Gate
◆ push 属对外操作，无论分支是否已关联远程、是否首次推送，一律先经用户确认。

Commit Message 前缀速查

常用前缀

  • feat: 新功能 — 例：添加用户登录模块
  • fix: 修复Bug — 例：修复分页总数计算错误
  • docs: 文档 — 例：更新API接口文档
  • refactor: 重构 — 例：提取公共校验逻辑
  • style: 样式/UI — 例：调整按钮间距

其他前缀

  • test: 测试 — 例：补充订单模块单元测试
  • build: 构建/依赖 — 例：升级Spring Boot到3.2
  • perf: 性能优化 — 例：优化列表查询索引
  • chore: 杂项 — 例：更新.gitignore

关键信息

触发条件

  • 代码改完了，想提交到当前分支
  • 需要自动生成符合规范的 commit message
  • 想提交但希望 push 前先人工确认
  • 触发词：提交代码 / commit / push / 帮我提交

排除边界

  • 分支合并/冲突解决 → 手动操作
  • 交互式 rebase → 需要手动确认
  • 修改历史提交 → git commit --amend 单独处理
  • Force push → 危险操作，需手动执行

产出物

  • 终端直接执行 git 命令，实时显示结果
  • 提交成功：分支名 + commit hash + commit message
  • Push 成功：远程分支名

关键原则

一次确认再动

提交前只问一次：目录 + 范围合并确认，防止误提交且不重复打扰。

一次一件事

不相关变更拆成多次提交，每个 commit 做一件事。

注释即文档

Commit message 让别人和三个月后的自己一眼看懂改了什么。

Push 需人工确认

提交后不自动 push，先展示摘要并询问，确认后才推送。
